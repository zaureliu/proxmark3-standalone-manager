What is still missing before any public binary copy:

1. The corresponding source of the exact Qt 6.12.0 and PySide6 6.12.0
   binaries conveyed in a local build is not offered to recipients by the
   distributor. A copy kept only on the build machine is not that offer. A
   generic link to the Qt website is not that offer. The offer has to stay
   under the distributor's control for the period the license requires, and
   it has to include any modifications. This project did not modify Qt or
   PySide6.

2. It has not been shown that the Qt binaries inside the PySide6 6.12.0
   wheel are the unmodified result of building the public source archives
   named in CORRESPONDING-SOURCE.md. Until that is shown, the corresponding
   source of the binaries actually shipped cannot be certified.

3. The package does not include the object files or build scripts needed
   to relink PySide6 against a modified Qt. Replacing a DLL in place is
   documented and can be tested. That test does not prove a modified Qt
   rebuild.

4. Qt's own third-party notices (for libraries Qt bundles) live in the
   corresponding source tree. They are not a substitute for item 1, and
   they are not all copied into a built folder as separate files.

Do not upload a zip that contains the executable. Permission to publish
the source repository is not permission to publish the binary package.
